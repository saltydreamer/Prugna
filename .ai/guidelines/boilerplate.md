# Boilerplate conventions

## Stack
- Laravel 13 + Fortify (headless auth) + Spatie Permission + Inertia v3 + Vue 3 (`<script setup>`, plain JS) + Vuetify 4 + Ziggy. Database: MariaDB (SQLite in-memory for tests).
- UI copy is Italian. Server-side strings go through `__()`; validation messages live in `lang/it`.

## Authorization
- Permissions are defined ONLY in `App\Enums\Permission`; system roles in `App\Enums\Role`. After adding a case run `php artisan permissions:sync` (also called by the seeders).
- `super-admin` owns every permission through `Gate::before` in `AppServiceProvider`, but policies (`UserPolicy`, `RolePolicy`) still apply their structural rules (no self-delete, system roles not deletable, last super admin protected).
- Authorize in controllers with `$this->authorize()` / Form Request `authorize()`; the frontend uses `usePermissions().can()` only to hide UI.

## Notifications
- Every in-app notification extends `App\Notifications\AppNotification` and implements `title()` / `message()` (optionally `icon()`, `color()`, `actionUrl()`, `actionLabel()`). It is stored in the database and also mailed when the user enabled `email_notifications`.
- Notifications are queued (`ShouldQueue`): a worker must run (`composer dev` starts one).

## Registry (Anagrafiche)

- `Organization` (soft deletes = "archiviata", read-only until restored) has many `Location` (sedi) and `Contact` (contatti). Routes under `registry.*`; locations/contacts are nested and scoped (`scopeBindings`).
- Exactly one primary location/contact per organization, enforced by `App\Models\Concerns\HasPrimaryFlag` (first record is primary, deleting the primary promotes another).
- Italian fiscal data: `App\Rules\ItalianVatNumber` / `ItalianTaxCode` validate check digits; normalize with their `normalize()` before storing.
- Permissions `organizations.*`; `OrganizationPolicy` also covers locations and contacts (update on the organization).
- Nested API resources returned inside another resource must be `->resolve()`d, otherwise Inertia wraps them in `data`.

## Catalog (Prodotti e servizi)

- `Product` (type product/service, unit `UnitOfMeasure`, optional `BillingPeriod` for recurring services only), `ProductCategory`, `VatRate` (0% rates need a FatturaPA `nature` N1–N7 and a legal reference), `CustomerPrice` (fixed price OR discount % per organization, optional expiry).
- Always compute the price for a customer with `App\Actions\Catalog\ResolvePrice` (agreed price > agreed discount > list price; expired agreements ignored).
- Money: decimal(12,4) columns cast to strings; the frontend formats with `formatMoney()` from `@/utils/format`.
- Codes are generated by `Product::nextCode()` (P00001 / S00001) when left empty.
- Large option lists for dialogs are `Inertia::optional()` props loaded with `router.reload({ only: [...] })` when the dialog opens.

## Settings

- `App\Support\Settings` (scoped singleton, cached): key/value settings edited in Impostazioni (`company.*`, `mail.*`, `quotes.*`, `fiscal.*`). `mail.password` is stored encrypted and never sent to the frontend.
- SMTP from the UI is applied by `App\Support\MailSettings` when the mail manager is resolved; saving restarts queue workers.
- `PaymentTerm` (FatturaPA method MPxx, days, end of month); organizations have a default `payment_term_id`.

## Quotes (Preventivi)

- `Quote` + `QuoteLine` (types item/section/text, optional lines counted only when selected). Always save through `App\Actions\Quotes\SaveQuote` (numbering PRV-00001, customer snapshot, totals) and compute totals with `QuoteTotals` (mirrored in `resources/js/utils/quoteTotals.js`).
- Status flow: draft → sent → accepted/rejected; sent quotes past `valid_until` become expired via `quotes:check-expiry` (scheduled daily, also reminds owners 3 days before). Only drafts are editable/deletable; accepted quotes are final.
- Visibility: owners see their own quotes; `quotes.supervise` sees everyone's (`Quote::visibleTo()`, `QuotePolicy`).
- Customers answer on the public page `/q/{public_token}` (no login, rate limited); the owner gets `QuoteActivityNotification`.
- PDF: `App\Support\QuotePdf` + `resources/views/pdf/quote.blade.php` (dompdf, DejaVu Sans with font subsetting).

## Orders and invoices (Ordini e Fatture)

- Shared document infrastructure: `DocumentTotals` (line rounding + VAT per rate), `SyncDocumentLines` (replace lines freezing VAT), `DocumentNumber::next()` (yearly numbers `ORD-2026-0001`, `FT-2026-0001`, `NC-2026-0001`, row lock + unique index), `CustomerSnapshot`, `IsDocumentLine`.
- `Order` + `OrderLine` (`quantity_invoiced`): created from an accepted quote with `SaveOrder::fromQuote()` (one per quote) or by hand. Customer and lines are editable only while nothing is invoiced (`Order::isEditable()`); `refreshInvoicedQuantities()` recomputes from invoices (drafts included) minus issued credit notes. Permissions `orders.view` / `orders.manage`; PDF "Conferma d'ordine" via `OrderPdf`.
- `Invoice` + `InvoiceLine` (types invoice TD01 / deposit TD02 / credit_note TD04, series FT/NC). Build drafts with `BuildInvoice` (from quote: full/deposit; from order: full/selection/deposit; credit note), save with `SaveInvoice` (freezes regime, withholding and pension fund from `fiscal.*`, keeps the "Rimborso imposta di bollo" system line in sync), issue with `IssueInvoice` (`problems()` lists what blocks issuing; numbering only at issue time, chronological order enforced). Issued invoices never change: correct them with a credit note.
- Fiscal totals: `InvoiceCalculator` (pension fund on the taxable, withholding, split payment, virtual stamp duty > 77.47 €), mirrored in `resources/js/utils/invoiceTotals.js`. Deposits are deducted in the balance as negative system lines (`deducts_invoice_id`), only once issued.
- FatturaPA XML: `App\Support\FatturaPa\FatturaPaXml` (FPR12/FPA12). Strings must be Basic Latin/Latin-1 (`text()` transliterates). `FatturaPaXmlTest` validates against the official XSD in `tests/Fixtures/fatturapa`.
- Permissions `invoices.view`, `invoices.manage` (drafts), `invoices.issue` (issue, credit notes). PDF courtesy copy via `InvoicePdf` (`resources/views/pdf/invoice.blade.php`, all PDFs extend `pdf/layout.blade.php`).

## Purchases (Acquisti) and rebilled costs

- Organizations have roles `is_customer` / `is_supplier` (a supplier order marks its supplier automatically).
- `PurchaseOrder` + `PurchaseOrderLine` (numbering `OF-2026-0001`, statuses draft/sent/confirmed/received/cancelled), saved with `SavePurchaseOrder`. Optional `order_id` (customer order; forces `customer_id` to its customer) and `customer_id` (who the costs are charged to). Lines are at cost; `rebill` + `markup_percent` mark costs to charge back (ignored without a customer). Permissions `purchases.view` / `purchases.manage`. PDF via `PurchaseOrderPdf` (never shows customer or markup); email via the generic `App\Mail\DocumentMail` + `DocumentSendDialog.vue`.
- Rebilling: `App\Actions\Purchases\RebillCosts` lists pending costs (`PurchaseOrderLine::toRebill()`: rebill lines of sent/confirmed/received orders without an invoice line, credit notes excluded) and builds the invoice line (`purchase_order_line_id`, net cost + markup, same VAT). Offered in the invoice editor (`RebillCostsDialog`, endpoint `sales.invoices.lookup.costs`) and when invoicing an order (`include_costs`). `InvoiceRequest` checks customer, committed status and single use; credit notes drop the link. Supplier orders with charged-back lines are frozen (`PurchaseOrder::isEditable()`).
- Order page shows costs and estimated margin (revenue + markups − costs not charged back).

## Frontend
- Pages: `resources/js/pages/**` (lowercase directory, e.g. `admin/users/Index`). Layout is chosen automatically in `resources/js/app.js` (`auth/*` → `AuthLayout`, else `AppLayout`).
- Reusable components: `resources/js/components`; composables: `resources/js/composables`.
- Links: use `useInertiaLink().link(route('name'))` with `v-bind` on Vuetify components (`v-btn`, `v-list-item`...).
- Toasts: server side `Inertia::flash('toast', ['type' => 'success', 'message' => '...'])`; client side `useToast()`.
- Confirmations: `await useConfirm().confirm({...})`.
- Shared props: `auth` (user, roles, permissions), `inbox` (unread_count, latest), `app`, `status` (Fortify).
- Component defaults (variants, density...) are set once in `resources/js/plugins/vuetify.js`.

## Quality
- `php artisan test` (feature tests per area in `tests/Feature`), `vendor/bin/pint`, `npm run lint`, `npm run format`.
